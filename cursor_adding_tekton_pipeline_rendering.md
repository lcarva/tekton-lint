You're absolutely right! I apologize for the confusion. PAC (Pipelines-as-Code) resolvers are indeed different from Tekton resolvers. Let me clarify:

## PAC Resolvers vs Tekton Resolvers

**PAC Resolvers:**
- Used by Pipelines-as-Code to resolve tasks from local files in a `.tekton/` directory
- Inline task definitions from the same repository
- Used during PAC processing, not during Tekton execution

**Tekton Resolvers:**
- Used by Tekton itself during pipeline execution
- Resolve tasks from remote sources like:
  - **Bundles resolver**: OCI registries (e.g., `quay.io/konflux-ci/tekton-catalog/task-show-sbom:0.1@sha256:...`)
  - **Git resolver**: Git repositories
  - **Cluster resolver**: Tasks in the same cluster
  - **HTTP resolver**: HTTP endpoints

Looking at your sample pipeline, it uses **Tekton bundle resolvers** like:
```yaml
taskRef:
  params:
    - name: name
      value: show-sbom
    - name: bundle

    - name: kind
      value: task
  resolver: bundles
```

3. **For Cluster resolvers**: Query the Kubernetes API
4. **For HTTP resolvers**: Make HTTP requests
